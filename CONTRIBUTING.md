# Contributing to Besidka

Thanks for your interest in Besidka. Here is how to take part.

## Issues are welcome

Found a bug, or have an idea for a feature? Open an
[issue](https://github.com/besidka/besidka/issues/new/choose) and pick the
matching template (see [`.github/ISSUE_TEMPLATE`](.github/ISSUE_TEMPLATE)). The
more concrete it is, with steps to reproduce, what you expected and what
happened, the faster it can be acted on. For questions and open-ended ideas use
[Discussions](https://github.com/besidka/besidka/discussions).

In the AI era a code change is cheap to produce and expensive to review, so the
maintainer prefers a well-described issue over a drive-by pull request. A clear
problem statement is the most useful contribution.

## Security

Do not open a public issue for a vulnerability. Follow [SECURITY.md](SECURITY.md)
to report it privately.

## Forking and self-hosting

Fork it, run it, change it for yourself. Besidka is released under the MIT
license (see [LICENSE](LICENSE)) and self-hosting on your own Cloudflare account
is encouraged. The README covers the setup.

## Code contributions

Code contributions are by invitation only. Propose the change in an issue first;
if it fits, the maintainer may add you as a collaborator for that change. Pull
requests can only be opened by collaborators (a repository setting), so there is
no pull request form for anyone else.
